# 视觉设计与验收

## 目标视觉

查看 `assets/style-reference.png` 的全图和 `assets/poster-default-reference.png` 的默认宽度视图：白色纸面、窄中央主干、两侧大幅计算图，模块以细彩色虚线围合，操作节点使用饱和色填充与短标签。海报需要在“查看全图”下能读出拓扑，放大后能读到操作与形状。不要把一系列说明卡片排列成海报。

### 布局与层次

- 默认从约2600宽开始。左右模块各占约35–38%，中央主干约10–14%，其余留给模块间距和连线走廊。中央不要膨胀成占三分之一画布的文字栏。
- 首屏默认适配宽度；纵向滚动是海报的正常阅读方式。不能为了首屏装下全图，把所有文字缩到只剩色块。比较参考时分别检查“适配宽度”和“查看全图”，不要混用两种缩放判断排版。
- 主干默认从下向上：输入/embedding → 层组 → 最终混合/输出。若模型更适合另一方向，可以改变，但主干与模块内部箭头必须统一且有明确图例。
- 层组画重复括号与最小真实周期，层号和特殊注入单独标注。不要用“L0–N：某某”的段落框替代层堆叠。
- 层堆叠中的代表层应展开“残差读 → Attention/递归模块 → 写回 → MoE读/计算/写回”等实际边界。大量同构层用重复组压缩；只有类型切换、KV/索引来源改变或特殊注入需要单独表达。完整层清单放阅读视图的交互网格。若结构不周期重复，分组展示真实阶段，不伪造周期。
- 先为主干与侧面 DAG 估算高度，再选画布高度。约2600宽、2200–2500高可作为复杂模型的起点，不是硬限制。画布增高应源于不可压缩的运算，而不是逐层清单、等高模块卡或稀疏长连线。以代表子层或独立小面板拆解复杂模块，避免单侧面板把全图拉成长条。
- 侧栏按模块复杂度分配面积；复杂attention可能需要最大的面板。允许上下错落，勿将复杂模块压进等高卡片。
- 顶部居中模型名，次行放4–6个重要结构事实，第三行阅读方向/图例。标题不要抢占图的主体空间。来源revision和不确定性详情放阅读视图。
- 面板标题27–30、普通操作20–23、形状16–18、主标题约40；中英文行距至少1.4倍。正文中文不要被缩为无法辨认的脚注。调整布局/换行，不靠持续缩小字体解决溢出。

### 颜色有语义

`assets/theme.json` 是唯一配色来源，海报和详解沿用同一映射。

| 主题 | 语义 | 视觉 |
| --- | --- | --- |
| recurrent | 递归、线性注意力 | 青绿 |
| attention | 全局检索、稀疏/普通注意力 | 橙 |
| moe | 专家路由和计算 | 草绿 |
| residual | 残差读写、混合主干 | 紫 |
| memory | n-gram、条件记忆、查表 | 洋红 |
| vision | 视觉和辅助预测 | 蓝 |
| cache | 跨步状态、缓存 | 红灰虚线框 |
| neutral | 输入输出、普通操作 | 灰蓝 |

面板边框/关联线用accent，实心操作块用strong+白字，详解与辅助说明用pale+ink。浅色只用于辅助状态或分组，不要把全部运算节点变成低对比淡色大框。同一语义在两种视图不换色；编号与文字保证色盲读者仍可区分。

### 真正绘制计算图

- 一个节点表达一个操作或不可分的小链，例如“Linear → Sigmoid”；投影后的Q/K/V、gate/value、shared/routed等独立数据流用独立分支。
- 对加法、乘法、加权求和，用圆形 `+`、`×`、`Σ` 汇合节点；两条箭头停在空白处不构成汇合。
- 残差从实际输入处分叉，沿节点外侧绕行并接到加法节点。Q旁路、shared expert和gate/value等语义不同的支路不要省略。
- 缓存用红灰虚线状态框，连接写入与读取。标出动态长度/固定容量，图外说明精度和生命周期。
- 实线箭头仅表示真实计算依赖；展开关联是无箭头彩色虚线，并从主干对应模块到面板边界。可选路径另标“可选”。
- 先放节点，后走线；箭头端点在节点边缘留1–3px空间。不同路径使用各自走廊，不穿过模块标题、操作文字和状态说明。为关系复杂的支路分配空间，别用一段句子顶替。
- 正交线优先；不要让多条长斜线挤在一个输入端口。分叉用共享母线，算术汇合落在明确运算节点；Q、状态、选择索引可从汇合计算块的不同端口进入。线条经过其他节点边框时也要检查，文字未相交不代表路径正确。
- 操作框内1–2行短操作名和可选1行形状；长公式、免责声明、实现差异进入详解，不挤在节点内部。

## 阅读视图

模板提供深蓝概览头、指标卡、模块导航、白色内容分区、语义色流程节点。按 details.md 填写内容。海报采用饱和色短操作块；详解采用同语义的浅底深字节点，容纳可选形状与简短说明，不将海报字体同比例放大。大模型详解应有：整体主流程与层调度并列、各模块多分支计算流程、公式块和缓存框、来源区。仅为每节加颜色而仍然通篇段落，不算结构详解。

## 验收

1. **事实**：按固定配置核对层数、头数、状态、分支、归一化和参数口径。核对主干和展开图连接的是同一种数据。
2. **默认与全图**：1440×1000或更宽浏览器下保存默认视图及“查看全图”截图。默认视图的画纸应占据可用宽度，能够看清主要操作；全图检查主干粒度、宽展开、图文密度、视觉重心与颜色分布。若主干只是数十条层号，返回计算图设计。与样张或用户参考比较视觉语法，不强求同一模型的节点位置。
3. **局部**：以100%或导出PNG观察最复杂的两块。检查最长标签、线条穿字、节点溢出、箭头归属、断开的合流以及共享专家/残差是否真正有边。
4. **详解**：截图概览头和至少两个复杂模块的完整 section，另看实际视口截图。检查并列分支、嵌入说明、公式/状态配对以及与海报的语义配色。若 section 只有一幅巨大海报裁片接连续正文，重新编排。局部 SVG 的阅读字号应接近正文，而不是占满一屏的少量巨大标签；含 SVG 的流程也要在390px窄屏逐项可读。
5. **功能**：所有模块键盘跳转、双击、返回、缩放、拖拽、Ctrl/⌘滚轮、形状/缓存开关、窄屏均可用。正文无JS可读。
6. **导出/打印**：SVG可解析并独立渲染；PNG与画布倍率一致；无工具栏、裁切、黑底、选择框。海报打印全图，详解打印不是仅滚动容器可见区域。

`--artifacts` 保存默认/宽度/全图截图、每个海报关联章节的干净截图、导出、打印和布局诊断。`validation.json` 区分浏览器功能通过与待人工验收；`quality_warnings` 提示层清单主干、全宽巨大SVG、移动端小字等迹象。24个紧凑主干条、900px图高、24px阅读图中位字号和10px移动端字号仅是需要复查的启发式阈值，不是结构正确性的判据，不要通过增删无意义节点来消除提示。SVG getBBox检测不等同像素实际重叠；但不能以此为理由跳过视觉检查。打印和交互未运行时，报告其未验证。无需进行模型推理或编译。
